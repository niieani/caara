# Issue Tracker: fp

Issues and PRDs for this repo live in `fp`, not GitHub issues. Use the `fp` CLI for all issue-tracker operations.

`FP_AGENTS.md` is generated by `fp init` and is the source of truth for agent-facing `fp` workflow rules. Run `fp guide` for current project primers and command details.

## Conventions

- **Create an issue**: `fp issue create --title "..." --description "..."`
- **Create a subissue**: `fp issue create --title "..." --parent <id>`
- **Read an issue**: `fp context <id>`
- **List issues**: `fp issue list --status todo`
- **Search issues**: `fp search <query>`
- **Comment on an issue**: `fp comment <id> "progress..."`
- **Update status**: `fp issue update --status in-progress <id>` / `fp issue update --status done <id>`
- **View hierarchy**: `fp tree [parent-id]`

Use `fp issue` for task tracking. Do not use GitHub issues, markdown checklists, or built-in todo tools for project issue state.

## When a skill says "publish to the issue tracker"

Create an `fp` issue.

## When a skill says "fetch the relevant ticket"

Run `fp context <id>`.
