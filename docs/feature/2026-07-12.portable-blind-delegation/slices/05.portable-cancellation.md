# Portable cancellation

Expose explicit cancellation by portable turn identity. The live registry retains the Agent Turn
cancellation effect; Agent Turn remains the sole owner of driver cancellation, session-binding
completion/deletion, and concurrency release. Portable state atomically claims cancellation, then
persists the driver-owned outcome and session reusability in separate Agent-safe and human
observation records.

Cancelled turns are immutable terminal records. Repeated or naturally completed cancellation
requests fail explicitly; a Working record recovered after service restart cannot be cancelled
because its live driver handle no longer exists. The viewer renders outcome and session reusability,
while CLI wait/cancel results exclude all activity.

The durable state machine writes `Cancelling` before invoking the driver. This intent prevents a
crash after driver mutation from recovering as ordinary Working. A live process reconciles partial
terminal turn or observation writes without invoking driver cancellation twice. After restart, an
unresolved `Cancelling` record has no trustworthy live handle or known outcome, so cancellation
fails explicitly as unavailable instead of fabricating a terminal result.

Compiled diagnostic coverage exercises Interrupted, both Abandoned policies, and Terminated. It
also verifies reusable bindings persist, non-reusable bindings are deleted, cancellation details
remain capability-protected, and private activity does not enter CLI output.
