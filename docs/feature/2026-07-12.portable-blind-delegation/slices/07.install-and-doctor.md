# Slice 07: Installed portable delegation and doctor

Issue: CAARA-kfvifdxa

## Result

- Live `caara doctor` exercises the installed service's public portable start, capability viewer,
  and bounded wait contracts with the built-in diagnostic driver.
- Default service installation performs the same capability probe after prerequisite repair,
  service-manager start, and shallow health verification.
- Probe failures name service installation/start and execution-path repair prerequisites. A still
  working diagnostic turn is cancelled before doctor returns failure.
- Viewer HTML and diagnostic execution are embedded in the compiled binary; no repository checkout
  or separately installed viewer assets exist.
- Default uninstall preserves portable state and user config. Purge removes Caara-owned config and
  state directories while preserving sibling XDG content.
- Non-loopback service exposure explicitly covers portable endpoints and bearer-capability viewer
  activity.

## Verification

The process test compiles and runs the real binary/service/doctor path. Install, default uninstall,
and purge use injected filesystem and service-manager boundaries so the suite proves artifact
ownership and command ordering without mutating the developer's live `launchd` user domain.
